项目 2：不提供动作标签，让策略从奖励中学习

量化类比：不模仿已有交易员，直接针对一段交互中的长期目标优化。但机器人会主动探索、改变下一状态；环境交互预算与回报定义成为核心。

任务：让一个摆从随机位置摆到竖直向上并维持。输入为cos角度、sin角度、角速度；输出为[-2,2]之间的连续力矩命令。使用Gymnasium `Pendulum-v1`。

闭环：策略/随机探索收集(o,a,r,o_next) → SAC replay或PPO rollout → 更新策略/价值网络 → 保存 → 重新加载 → 未用于采集的初始条件下执行 → 加延迟或改变重力 → 对比失败。

```bash
uv run python loop02_reinforcement.py --algo sac --steps 10000
```

先读 `raw_experience.npz`：你现在不再拥有expert_action；reward是环境根据姿态、速度和控制开销计算的。模型不是预测reward标签后就完工，而是用交互记录改善未来动作。

SAC是off-policy方法，使用replay buffer复用经验，并在回报与策略熵之间权衡。PPO是另一条以新采集rollout进行受约束更新的路径。本项目直接调用SB3的实现，不让你先重写完整算法；读懂数据、预算与评测后，再进入其update函数。

```bash
uv run python loop02_reinforcement.py --algo ppo --steps 10000
```

相同的环境步数是样本预算对照，不代表GPU时间、梯度次数或超参数调优预算相同。PPO可能以整块rollout收集而稍微超过请求步数，以日志中的实际值为准。10k步并不保证两种算法都收敛；不能据此宣布算法优劣。

指标：总回报越高越好（本任务通常为负数，接近0更好）；辅助指标是满足角度<0.2rad且角速度<1rad/s的时间比例，属于练习自定义指标。原始Gymnasium任务没有二元成功标签，别自行添加后当官方指标。

环境扰动：2步观测延迟=100ms；重力由10改为12用于测试模型失配。两者分别测试。随机策略不依赖观测，因此延迟条件下它的结果不变是预期行为。

改动题：

- 进一步改用Reacher时，需要换奖励尺度和训练预算；不能直接把Pendulum超参数当成机器人通用配置。

可贡献任务：记录并复现一个TimeLimit处理、reward归因、checkpoint恢复或延迟wrapper的问题；或给特定任务增加经过维护者认可的评测脚本。
