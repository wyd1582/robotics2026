项目 3：先学物理系统如何变化，再用模型选择动作

量化类比：先建立市场/执行的情景生成模型，再搜索一段决策，并根据最新状态滚动重算。它最接近“预测模型+优化器”的组合。

任务仍为Pendulum，这样你可以把注意力放在方法差异。不同项目的action repeat、数据预算与planner算力不同，默认结果不能直接当公平算法排名。

```bash
uv run python loop03_world_model.py --quick
```

闭环：随机动作产生原始transition → 按episode分离训练和验证 → 学神经网络预测next_obs-obs → 检查一步/多步误差 → 用学到的模型预测候选动作序列 → CEM选择低成本序列 → 只执行第一段 → 获得真实模拟器新观测 → 重新规划。

被学习的函数不是π(o)=a，而是f(o,a)=o_next。本项目奖励函数已知，只学习动力学；不是图像生成世界模型，不是Dreamer、PETS或MBPO的完整复现。

规划器：随机采样一批动作序列，用模型向前展开，保留表现好的候选，更新采样分布，重复几轮。这个搜索称为CEM；执行首段并重规划称为MPC。默认每个动作保持3个环境步，执行后才重规划；预测跨度为horizon×repeat×0.05秒。

比较三组：随机控制、已知真实方程的MPC、学到动力学的MPC。已知方程参考仍受限于搜索预算和规划时域，不是数学上的全局最优上界。

先看 `model_error.png`：一步预测误差小，多步递推仍可能累积错误。再看 `comparison.png`：模型误差与控制表现不一定单调相关，因为优化器会主动走到模型不熟悉的区域。

训练数据全部来自随机rollout。由规划器新访问到的状态构成第二轮可收集数据，这是下一步“模型 -> 规划 -> 新数据 -> 重训”的练习；第一版脚本已经闭合执行反馈回路，但尚未自动实现迭代动力学重训。

改动题：

- 改horizon：短视可能无法完成摆起，太长可能放大模型误差与计算成本。
- 改candidates：增加搜索能否补偿差模型？是否反而更会利用模型漏洞？
- 改训练episodes：比较一步MSE、多步MSE与闭环回报，找出排序不一致的案例。
- 在相同新增transition数量下，比较随机数据与MPC访问状态的数据，再训练模型。评测使用新冻结seeds。

进阶：在模型集成中记录分歧，用于限制高不确定性的计划；分歧不天然等于校准后的概率。要复现PETS，应加入其概率动力学集成与trajectory sampling，并采用原任务/预算；本项目只是进入这条路线的可检查起点。

口试：为什么优化器可能找到模型误差最大的动作？为什么离线预测更准的模型不一定控制更好？action repeat在哪里改变了控制频率？

参考：[Pendulum官方环境](https://gymnasium.farama.org/environments/classic_control/pendulum/)、[MBRL-Lib及PETS示例](https://github.com/facebookresearch/mbrl-lib)。MBRL-Lib用于阅读方法结构，本练习没有安装它或依赖其旧环境组合。
